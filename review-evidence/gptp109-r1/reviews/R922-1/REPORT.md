The floor implementation is safe across the arithmetic result's full domain. After arithmetic halving, D lies in `[-2^62, 2^62−1]`; adding 800 cannot overflow a signed 64-bit value. The arithmetic sign mask subtracts D+800 exactly when D<−800, otherwise it subtracts zero. Subtracting 801 from the resulting value also cannot overflow; its sign correctly separates 800 from 801. The unsigned 32-bit compare sees only the extracted 0/1 sign bit. The scratch write retains all 64 bits, and the next accepted Sync pair consumes that signed value. No response-identity, multi-response, ratio, reset, timer, or handshake logic is changed.

Publishing the floored value is consistent with the ruling's intent and the parent consumer. The engine's word is only 32 bits (`KL_gptp_engine.sv:1221`). Sending an arbitrary negative 64-bit raw D through that word could lose the negative sign. Flooring first preserves a signed value between −800 and −1 for every negative D. The [parent clamp](https://github.com/kebag-logic/milan-fpga/blob/e275d7950ef3385753e6a15d2e191ba855b171ed/hdl/ieee8021as/gptp_plane/KL_gptp_shadow.sv#L770) then publishes zero atomically on commit. Thus D=−263 is used as −263 and reads zero publicly; D<−800 is used/published by the engine as −800 and also reads zero publicly. The PR explicitly explains this distinction. The ruling does not require exporting an unfloored diagnostic value through a wider interface.
